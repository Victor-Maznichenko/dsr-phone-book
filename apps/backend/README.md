
# OpenAPI Generated JavaScript/Express Server

## Обзор
Этот сервер был сгенерирован с помощью проекта OpenAPI Generator. Генератор кода и созданный им код позволяют разрабатывать систему с подходом "API-First", при котором контракт API является основой проекта, а ваш код и бизнес-логика стремятся соответствовать этому контракту.

### Необходимые условия
- NodeJS >= 10.6
- NPM >= 6.10.0

### Запуск сервера
#### Это длинное объяснение, но важно разобраться. Пожалуйста, найдите время, чтобы внимательно прочитать.
1. Каждой операции будет добавлен элемент x-eov-operation-handler: controllers/PetController — он указывает, куда направлять вызов.
2. Используется Java-приложение и NodeJS-скрипт, преобразующие operationId в метод (в camelCase). Обратите внимание на соответствие operationId именам методов в папках controllers и services.
3. Вкратце: приложение начинается с index.js (позже сюда подключите БД). Затем вызывается expressServer.js, где инициализируется Express и валидатор OpenAPI. Все вызовы к API, описанному в openapi.yaml, попадают в controllers/{имя_тега}.js, где методы очень короткие. Бизнес-логика — в controllers/Controller.js, затем в services/{имя_тега}.js.

### Тесты
К сожалению, модульные тесты пока не написаны. Однако проект уже включает всё необходимое: mocha, sinon и другие библиотеки указаны в package.json и будут установлены при npm install.

### Просмотр и тестирование API
(Предполагается, что config.js не изменён):

- Документация API и список доступных эндпоинтов:  
    [http://localhost:8080/api-docs/](http://localhost:8080/api-docs/)
- Скачать спецификацию OpenAPI:  
    [http://localhost:8080/openapi](http://localhost:8080/openapi)
- Каждый вызов эндпоинта из спецификации возвращает 200 и список всех переданных параметров и объектов.
- Эндпоинты, требующие авторизации, сначала вернут [401 Unauthorized](https://developer.mozilla.org/en-US/docs/Web/HTTP/Status/401), пока вы не настроите обработчики безопасности.
- **Внимание**: сервер _не поддерживает_ тело запроса в формате XML.

### Версия Node и рекомендации
Код написан на Node версии 10.6 и соответствует [правилам ESLint от Airbnb](https://github.com/airbnb/javascript).

### Файлы проекта
#### Корневая директория:
Помимо `package.json`, `config.js`, и логов:

- **logger.js** — настройка логгера (используется `winston`, можно заменить под свои нужды).
- **index.js** — основной файл запуска приложения. Минималистичный, чтобы позволить запуск с разными параметрами (например, другой конфиг или логгер).
- **expressServer.js** — ядро Express-сервера. Здесь происходит инициализация Express, OpenAPI-валидатора и OpenAPI UI. Используется [express-openapi-validator](https://www.npmjs.com/package/express-openapi-validator), который валидирует все входящие запросы по `openapi.yaml`. При успешной валидации в запрос добавляется объект `openapi`.

#### `api/`
- **openapi.yaml** — основной контракт OpenAPI. Содержит всю информацию для работы API Gateway. Внешние ссылки на схемы отсутствуют.
    

#### `utils/`
Пока содержит только:

- **openapiRouter.js** — маршрутизация к бекенду. Если в запросе есть объект `openapi`, берёт значения `x-openapi-router-controller` и `x-openapi-router-service` из YAML, а также `operationId`. Затем перенаправляет запрос в нужный `controller`, который вызывает соответствующий `service`.
    

#### `controllers/`
После валидации запроса он попадает в контроллер, где извлекаются параметры и вызывается нужный `service`.

- **index.js** — регистрирует все контроллеры. Если вы хотите использовать свой контроллер, подключите его здесь и защитите от перезаписи генератором.
    
- **Controller.js** — основная бизнес-логика: извлекает параметры, обрабатывает запрос, строит HTTP-ответ.
    
- **.js** (авто-сгенерированные файлы) — каждая операция из `openapi.yaml` реализуется как метод, который вызывает `Controller.js`.
    

#### `services/`
Здесь начинается бизнес-логика. Каждый эндпоинт в YAML ссылается на `x-openapi-router-service`, имя которого соответствует классу. `operationId` — имя метода.

- **index.js** — регистрирует все сервисы. Для добавления пользовательской логики, подключите нужный сервис вручную.
- **Service.js** — вспомогательный класс с методами для создания ответа (успешного или с ошибкой). По умолчанию: 200 для успеха, 500 — ошибка. Лучше переопределять при необходимости.
- **.js** (авто-сгенерированные) — шаблоны Promises с `try/catch` для каждой операции. Возвращают результат в контроллер.

#### `tests/`
- **serverTests.js** — базовые проверки: сервер работает, эндпоинты из YAML возвращают 200, неизвестные — 404.
- **routingTests.js** — проход по всем эндпоинтам из YAML, отправка тестовых запросов, проверка ответов.
- **additionalEndpointsTests.js** — проверка ручек вне YAML — что возвращают 200.

В будущем планируется добавить тесты, которые будут сравнивать ответы с тем, что указано в `openapi.yaml`. Они будут падать до тех пор, пока команда разработки не приведёт поведение к соответствию.

#### `models/`
Пока концепт. Идея — описывать объекты из YAML как модели, чтобы использовать их в модулях вместо "сырых" JSON. Возможно, идея не приживётся, но оставлена для обсуждения.
